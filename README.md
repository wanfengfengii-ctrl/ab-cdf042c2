# 地震预警短二进制码编配工作台

为地震预警中心调度员设计的纯静态前端工具：为 **5–8 类警报**编配短二进制码字，
在受限带宽中让高频警报优先获得更短码字，且任何连续电文都能被唯一拆分（前缀码）。

## 功能

- 录入每类警报的 **名称**、**正整数预计发送频次**、**码长闭区间**（1–24 bit），以及 **0–3 条保留前缀**；
- 每类警报恰分配一条码字，码字两两不互为前缀，且不落入、也不遮蔽保留前缀所代表的区间；
- 方案取舍顺序：**加权码长总和最小 → 最大码长最小 → 按警报输入顺序展开的字典序最小**（精确求解，非启发式）；
- 结果区展示 **二叉码树**（分配码字 / 保留分支 / 未使用分支）与 **明细表**（码字、码长、加权贡献、总成本）；
- 无解时明确说明「没有可用的完整分配」并给出排查建议；
- 输入任何变动后旧结论立即作废；草稿自动保存在本机浏览器（localStorage），可继续修改。

## 目录结构

```
src/            静态站点（index.html / styles.css / app.js / solver.js）
tests/          node:test 测试（求解器单测 + 暴力枚举对拍 + DOM 集成测试）
scripts/        build.mjs 构建检查、serve.mjs 本地静态服务、verify.sh 核验脚本
Dockerfile      多阶段：测试+构建 → nginx 托管（含 HEALTHCHECK）
Dockerfile.verify  一次性核验服务镜像
docker-compose.yml  app（可配置宿主机端口）+ verify（一次性服务）
nginx.conf      静态服务配置，含 /health 健康检查地址
```

## 本地运行（无需 Docker）

```bash
npm test          # 代码测试（求解器 + DOM 集成）
npm run build     # 构建检查并输出 dist/
npm run serve     # 本地静态服务，默认 http://127.0.0.1:8080 （PORT 可改）
```

也可以直接用浏览器打开 `src/index.html`。

## Docker 运行

```bash
# 构建并启动静态服务（默认宿主机端口 8080）
docker compose up -d app

# 可配置宿主机端口，例如 9000
APP_PORT=9000 docker compose up -d app

# 健康检查地址
curl http://127.0.0.1:9000/health   # => ok
```

## 一次性核验服务 verify

`verify` 服务依次执行 **代码测试 → 构建检查 → 健康地址冒烟**，然后以退出码结束
（0 = 全部通过，非 0 = 任一步骤失败）：

```bash
# 方式一：随依赖一起启动，并以 verify 的退出码作为整组命令的退出码
docker compose up --exit-code-from verify verify

# 方式二：服务已在运行时单独执行
docker compose run --rm verify
```

## 求解算法说明

- 码空间被保留前缀切分为「可用子树森林」；森林中每棵子树只用深度即可精确刻画容量
  （把长度 `l` 的码字放进深度 `d` 的子树，该子树被替换为深度 `d+1..l` 的兄弟子树）。
- 阶段一：对长度向量做分支限界搜索（按频次降序 + Kraft 度量剪枝 + 记忆化森林可行性判定），
  求出最优的 (加权码长总和, 最大码长)。
- 阶段二：在最优解集合中，按警报输入顺序逐类选取字典序最小且仍能以最优成本衔接的码字。
- 测试包含与指数级暴力枚举的随机对拍，保证三个优化层级与字典序 tie-break 完全一致。
